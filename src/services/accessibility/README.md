# services/accessibility

Batch 524 (PS-491, WCAG 2.1 AA). Source-level accessibility checks.

| File | What it does |
|---|---|
| `a11yAudit.ts` | `auditAccessibility(source)`: pure, text in, findings out. Three kinds of finding: **clickable** (an `onClick` on a `div`, `span`, `li`, `td`, `tr`, `img`, `svg` element… that can't be used from the keyboard), **unnamed-field** (a `select`, `input` or `textarea` with no name a screen reader can read) and, since Batch 566, **container-without-button** (an element spread with `{...clickableContainer(…)}` that holds no real `<button>` before its own closing tag). Batch 567 adds `nestedInteractive(source)`: an element spread with `{...pressable(…)}` or `{...switchable(…)}` that holds another control (a button, link, field, `CapabilityButton` or another pressable); `pressable(handler, { role: null })` (a table row) isn't counted, and an element the audit can't read is reported rather than passed. Since Batch 568 the guard runs it over every UI file, with no exception list. What it covers: elements made into controls with `pressable` / `switchable`, and the controls in `CONTROL_INSIDE` (button, link, input, select, textarea, `Link`, `NavLink`, `CapabilityButton`, another pressable). Since Batch 569 it also checks a `<button>`, and an element given a control's role by hand (`role="button"`, `"checkbox"`, `"switch"`, `"radio"`, `"tab"`, `"option"`, `"menuitem…"`, `"slider"`, `"img"`). Not seen: a role set by an expression (`role={x}`), `<a role="button">`, custom components that render a button (`<Button>`), and a hand-made control without a role inside a control. The browser check (axe nested-interactive) covers the screens it opens. Batch 569 also reads each file with the TypeScript parser to set comments aside (once per file, shared by the checks), so `//` in on-screen text is no longer taken for a comment; the old pattern had also blanked about 380 lines of `QualityAssurancePage.tsx` after a `/*` inside a `//` comment, and those lines are now checked (they pass). Comments are ignored. |
| `a11y.guard.test.ts` | Runs the audit over every UI `.tsx` file in `src/`, with **no exception list**, plus self-tests of the audit. A new clickable `div` without `{...pressable(…)}` / `{...switchable(…)}` (or its own role, tab stop and key handler), or a new unnamed field, fails the suite. |

What isn't counted as "clickable": a handler that only stops the click from bubbling (the inside of a modal), and a backdrop (class `overlay` / `backdrop` / `scrim` / `mask`), which is a mouse shortcut for the window's own Close button.

The browser check (axe-core in a real Chromium) is `e2e/a11y.spec.ts` at the repo root (`npm run test:a11y`). It sees only the screens it opens; this guard sees every file.
