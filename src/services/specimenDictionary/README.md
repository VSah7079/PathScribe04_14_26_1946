# services/specimenDictionary/

THE real backend for the Specimen Dictionary (SpecimenEntry) — what Accession, the Synoptic editor, and Search all actually consume.

**Pattern:** Standard interface/mock/firestore pattern (added June 2026, closing a real prior gap).

## Files

- **`ISpecimenDictionaryService.ts`** — Its own header documents the prior gap directly: this dictionary was the one domain NOT following the standard pattern (useSpecimenDictionary.tsx called localStorage directly, inline, no interface). Also independently names services/specimens/ISpecimenService.ts as a properly-shaped but completely dead service that existed alongside it — confirmed and deleted during the July 2026 cleanup, corroborating this file's own documentation.
- **`specimenTypes.ts`**'s `SpecimenEntry.defaultBaseCptCode` — **New.** Real, optional field for a real coder's specimen-type-specific base surgical pathology CPT code (e.g. "Breast core needle biopsy" → 88305), per direct guidance that the lab's own AMA license covers this - this app never fabricates the mapping itself, only the mechanism. Real, per-case resolution already existed to build on: `Specimen.specimenDictionaryEntryId` was already a real, persisted link (set at Accession), just not yet used for CPT purposes - see `services/billing/codeMapTable.ts`'s `resolveSpecimenDictionaryBaseCptCode()`. Editable through the existing Specimen Dictionary admin screen (`components/Config/System/SpecimenDictionarySection.tsx`) - a real, silent gap was found and fixed while wiring this in: the form field rendered and accepted input, but the save function (`buildEntry`) never actually copied the value into the saved entry, so it would have been dropped on every save.
- **Real, researched demo data (35 of 60 seed entries), per direct request.** `scripts/terminology-sources/specimens-starter.json`'s `defaultBaseCptCode` values were verified via direct search against multiple sources, including an official Medicare Administrative Contractor (Palmetto GBA) specimen-level list — not fabricated, but explicitly NOT a substitute for real coder review before any production/billing use (see the file's own `notes` field for the full disclosure, and `services/billing/README.md` for the fuller research trail). Deliberately left blank for Cytology, FNA, Molecular, Autopsy, Consult, and Gross-Only entries, which use different, unverified CPT code families this app hasn't researched.
- **`mockSpecimenDictionaryService.ts`** — **Real, clinically significant bug found and fixed in a systematic bad-query audit (Aug 2026).** The CAP/ASCO biomarker fixation-time compliance gate (`FixativeTimeGateModal.tsx`, blocking sign-out via `SynopticReportPage.tsx` until fixative time is confirmed) is set here on seed data via `e.subspecialty === 'Breast Pathology' ? { ...e, requireFixativeTimeBeforeSignout: true } : e`. It previously checked `e.type === 'Breast'` — but real `SpecimenEntry.type` values are procedure categories (Biopsy, Resection, Excision, etc.), never organ/subspecialty names. Confirmed directly against the real 60-entry `specimens-starter.json`: zero specimens ever had the flag actually set, meaning this real clinical safety gate never fired for any real breast specimen. Fixed to check `subspecialty === 'Breast Pathology'`, verified directly to correctly capture all 7 real breast-pathology-relevant specimens — including Mastectomy and axillary/sentinel-node entries that don't even contain the word "breast" in their name, which a name-substring check would have missed too.
