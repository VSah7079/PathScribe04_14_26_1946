# types/autopsy/

Core data model for the Autopsy Pathology Module (PS-261, RFP-APLIS-2026-GLOBAL §3.1.C). The real logic that consumes this type lives in `services/autopsy/` — see that folder's own README for what's actually built on top of it.

## Files

- **`AutopsyCaseDetails.ts`** — `caseAuthority` (`'statutory_judicial' | 'hospital_consented'`), `ForensicAuthorization` (now tracking both the real verbal order that authorizes intake/refrigeration and the real written order required before gross examination — confirmed directly against real research across all 14 target jurisdictions), `HospitalConsentRecord`, PAD/FAD report snapshots, organ retention, ancillary holds, and (Batch 468) an append-only `custodyLog` for forensic cases.
- **Batch 468 — `HospitalConsentRecord` redesign.** The old `revokedOrNarrowedAt`/`revocationNote` pairing carried a documented TODO: it conflated full revocation with mere scope narrowing, and `services/autopsy/resolveAutopsyGrossExaminationGate.ts` blocked on either conservatively. Replaced with the structured redesign that TODO itself called for: `status: 'active' | 'narrowed' | 'revoked'` (only `'revoked'` hard-blocks the gate), `excludedOrgans: AutopsyOrganCode[]` (organs the consent excludes), and `retentionPermitted: boolean` (whether consent permits retention beyond the diagnostic gross exam). Both new fields are the first real, machine-enforced reading of consent scope — see `services/autopsy/resolveAutopsyConsentScopeViolation.ts`.
- **Batch 468 — `AutopsyCustodianType` / `AutopsyCustodyTransferEvent`.** New types for forensic chain-of-custody: who held an item, who it was transferred to (by role — pathology department, medical examiner, law enforcement, funeral home, family, other), who released and who received it. Mirrors the existing `MaterialLocation`/`locationHistory` append-only pattern (`types/case/Material.ts`) rather than inventing a new persistence shape, but carries the richer, forensic-specific fields a generic material-location entry doesn't. See `services/autopsy/recordAutopsyCustodyTransfer.ts`.
- Real, confirmed fix (per direct follow-up): this type was never actually attached to the app's real `Case` entity until this session — `Case.autopsy?: AutopsyCaseDetails` (`types/case/Case.ts`) is the real, missing link that makes accessioning an autopsy case possible at all.
- Real, confirmed correction (per direct follow-up: "Isn't the body usually the specimen?"): this type does NOT carry its own storage/location tracking. A body is a real `Specimen`, and `Specimen.locationHistory: MaterialLocation[]` already covers that — see `services/autopsy/resolveMortuaryStorageOccupancy.ts`'s own README entry for the full account of a duplicated mechanism that was built and then removed.
- **`AutopsyOrganCode.ts`** — the 31-organ canonical vocabulary. Batch 468 adds `parseAutopsyOrganCodeList()`, parsing a comma-separated consent-form field into this vocabulary, silently dropping unrecognized tokens (a consent form is filled in by clinical staff, not a developer).
- **Batch 469 — `AutopsyToxicologyOrder` / `AutopsyToxicologyResult`.** New types on `AutopsyCaseDetails.toxicologyOrders`: specimen description, analytes requested, lab, status, and the eventual result. `cancelledAt`/`cancelReason` existed on the order type from this batch but nothing set them until Batch 471's `cancelAutopsyToxicologyOrder.ts` — see that batch's own entry below. See `services/autopsy/orderAutopsyToxicology.ts` / `recordAutopsyToxicologyResult.ts`.
- **Batch 469 — `AutopsyCaseDetails.organRetentionDisposal`.** New field recording how retained organs/tissue were disposed of (method, timestamp, certificate reference, who recorded it), alongside the pre-existing bare `organRetentionTier`. See `services/autopsy/recordAutopsyOrganRetentionDisposal.ts`.
- **Batch 469 — consent narrowing/revocation.** No new type: this reuses Batch 468's `HospitalConsentRecord.status`/`excludedOrgans`/`retentionPermitted` fields, now with a real write site (`services/autopsy/applyAutopsyConsentStatusChange.ts`) that enforces them as one-directional — only the orchestration changed, not the shape.
- **Batch 471 — `OrganRetentionRecord`.** New type for `AutopsyCaseDetails.organRetentionDetail`: who holds retained organs/tissue and where, while retention is ongoing — distinct from `organRetentionDisposal` above, which only covers final disposal. A single current record, not a log; each update overwrites the last. See `services/autopsy/recordAutopsyOrganRetentionDetail.ts`.
- **Batch 471 — `cancelledAt`/`cancelReason` now real.** `AutopsyToxicologyOrder`'s own two fields (named above, under Batch 469) are now set by `services/autopsy/cancelAutopsyToxicologyOrder.ts` — the gap this file itself disclosed is closed.
- **Batch 471 — consent reinstatement.** No new type here either: reuses the same `HospitalConsentRecord` fields Batch 468 introduced and Batch 469 made narrow-only, now with a second, genuinely separate write site (`services/autopsy/applyAutopsyConsentReinstatement.ts`) that's allowed to widen them back — gated by its own capability, never the narrowing one.
- **Batch 472 — `organRetentionTierReason`.** New optional field on `AutopsyCaseDetails` itself: a free-text reason for the `organRetentionTier` selection, distinct from `OrganRetentionRecord.reason` above (which is about the retention *detail* — who holds it, where). Set by the same write site as `organRetentionTier` itself — no new type, no new write site.
- **Batch 473 — `AutopsyCaseAuthority`'s forensic-path value renamed.** `'medicolegal_forensic'` → `'statutory_judicial'`: the same jurisdiction-neutral key, no shape change. Ahead of the dedicated autopsy worklist (which will filter on this field) and the international terminology PathScribe needs (US Medical Examiner/Coroner and UK/Commonwealth statutory judicial autopsies are the same case type, differently named). `'hospital_consented'` unchanged.
- **Batch 475 — `AutopsyToxicologyOrder.specimenBarcode`.** New required field: a real, scannable specimen identifier, distinct from the existing free-text `specimenDescription`. Available on either `caseAuthority`. `AutopsyCustodyTransferEvent` gains one optional field, `toxicologyOrderId`, linking a (still forensic-only) custody-log entry to the toxicology specimen it's about — no new custody type or mechanism. See `services/autopsy/orderAutopsyToxicology.ts` / `recordAutopsyCustodyTransfer.ts`.
- **Batch 478 — `AutopsyGateOverrideEvent`.** New type for `AutopsyCaseDetails.gateOverrides`: every time `resolveAutopsyGrossExaminationGate.ts`'s hard stop was bypassed — which tier, the gate's own `blockedReasons` at that moment, the required written reason, who did it, when. Append-only, like `custodyLog`. Written only by `services/autopsy/signAutopsyReport.ts`, the one real write site the gate now actually blocks.
- **Batch 478 — `AutopsyOrganTag`.** New type for `AutopsyCaseDetails.organTags`: a per-organ gross-exam finding (`organCode` from the existing 31-code `AutopsyOrganCode` vocabulary, `status: 'normal' | 'abnormal' | 'not_examined'`, optional free-text `finding`, who recorded it, when). Append-only, like `custodyLog` and `toxicologyOrders` — a real per-organ history, since the same organ may be re-examined or corrected before sign-out. Deliberately a separate, case-level log rather than a field on the grossing template's own `EditorField` (which has no per-field organ association today — see `services/autopsy/recordAutopsyOrganTag.ts`'s own header comment for why). SNOMED mapping deferred, same as `AutopsyOrganCode` itself, pending PS-343 licensing.
- **Batch 479 — `AutopsyGateOverrideEvent.blockedReasons` now holds reason codes, not prose.** `services/autopsy/resolveAutopsyGrossExaminationGate.ts`'s own `blockedReasons` changed from literal English strings to a real union type (`AutopsyGrossExaminationBlockReason`), fixing the gap Batch 478 disclosed rather than leaving it. This field's own type stays `string[]` (kept decoupled from a service-layer type on purpose — `AutopsyCaseDetails.ts` doesn't import from `services/`), but the values it's given are now those same codes. See `services/autopsy/README.md`'s own Batch 479 entry for the full account, including a related, not-yet-fixed instance of the same gap in `resolveAutopsyBodyReleaseGate.ts`.
