    # 부록: 문제 해결 및 감사 로그 검증

    이 장은 세 부분으로 구성됩니다. 첫째는 문제 해결 매트릭스로, 관리자가 가장 자주 접하는 문제를 원인과 해결에 사용하는 화면과 함께 정리합니다. 둘째는 PathScribe가 표시하거나 기록하는 오류 코드의 색인입니다. 셋째는 시스템 로그 화면을 설명하고, 감사 로그에 담긴 내용을 검증하는 단계별 절차를 안내합니다. 용어집은 가이드의 마지막 장입니다(용어집).

    여기에 인용된 모든 메시지는 제품의 영어 원문입니다. 모든 코드는 소스에 존재하는 코드입니다. 계약서에 자리 표시자로만 있고 제품에서 사용되지 않는 코드는 수록하지 않습니다.

    # 문제 해결 매트릭스

    홈 › 관리자 가이드 › 부록 › 문제 해결 매트릭스

    상태: 구현됨

    매트릭스 사용 방법. 사용자가 보고한 증상을 찾고, 가능한 원인을 확인한 다음, 해결 방법을 따르십시오. "작동하지 않는다"는 보고의 대부분은 두 가지 중 하나입니다. 설정한 적이 없는 사전(빈 목록)이거나, 권한을 보유하지 않은 역할(비활성화된 버튼 또는 거부된 저장)입니다. 증상에 대문자 코드가 표시되면 오류 코드 색인에서 찾으십시오.

    가장 먼저 확인할 사항. 두 가지 확인으로 대부분의 질문에 답할 수 있습니다.

    1. 시스템 로그를 열고 해당 사용자의 이름 또는 권한 키를 검색하십시오. 거부된 권한 확인은 해당 권한과 사용자의 세션 역할을 명시한 Capability refused 항목을 기록합니다.
    2. 오류 로그 탭에서 보고된 시각 부근의 코드, 소스, 시간이 있는 미해결 오류를 확인하십시오.

    증상(사용자에게 보이는 내용) 가능한 원인 해결 화면
    케이스의 팀 창에 구성된 참여 유형이 없습니다와 함께 "System → Participation Types에서 유형을 설정하십시오."라는 안내가 표시됩니다. 참여 유형이 없습니다. 검사실에서 사용하는 유형을 추가한 다음 창을 다시 여십시오. 참여 유형
    테스트 인쇄 또는 라벨 창에 구성된 프린터 프로필이 없습니다라고 표시됩니다. 프린터 프로필이 추가되지 않았습니다. 라벨 프린터 모델마다 프린터 프로필을 추가하십시오. 프린터 프로필
    포매 또는 미세절편 스테이션에 구성된 프린터 없음 또는 구성된 프린터 프로필이 더 이상 존재하지 않습니다라고 표시됩니다. 슬라이드 분배 스테이션에는 This station isn't set up for slide-label printing.이라고 표시됩니다. 스테이션에 프린터 프로필이 없거나 프로필이 삭제되었습니다. 스테이션을 열고 현재 존재하는 프린터 프로필을 선택하십시오. 스캔 스테이션, 프린터 프로필

    라벨이 인쇄되지 않고 메시지에 GS1 GTIN이 설정되지 않았습니다. GS1 카세트 라벨을 인쇄하기 전에 인쇄 설정에서 설정하십시오.(또는 슬라이드 라벨)라고 표시됩니다. 시설에 GS1 GTIN이 입력되어 있지 않습니다. 인쇄 설정에 GTIN을 입력하십시오. 인쇄 설정

    수술실 대시보드에 No terminals configured yet이라고 표시됩니다. 수술실 터미널이 없습니다. 터미널을 추가하십시오. 수술실 터미널
    라우팅 규칙 창에 ⚠ 활성 풀이 없습니다. 먼저 세부 전공에서 "풀 / 작업 그룹"을 활성화하세요.라고 표시됩니다. 풀 / 작업 그룹 모드인 세부 전문 분야가 없습니다. 하나 이상의 세부 전문 분야에서 풀 / 작업 그룹을 켠 다음 규칙을 추가하십시오. 세부 전문 분야, 라우팅 규칙
    새 컨테이너 창에 No facility is currently configured with the Reference Lab role.이라고 표시됩니다. 참조 검사실 역할을 가진 시설이 없습니다. 시설 설정에서 한 시설에 해당 역할을 부여하십시오. 시설 사전

    # 저장 거부, 비활성화된 버튼, 열 수 없는 화면

    PathScribe는 권한을 두 번 확인합니다. 화면은 사용자가 할 수 없는 작업을 비활성화합니다. 그 작업 뒤의 서비스가 다시 확인하여 거부합니다. 운영 환경에서는 API 서버가 확인을 반복하며 최종 결정권을 가집니다. Superadmin을 포함하여 어떤 역할에도 우회 수단은 없습니다.

    증상 가능한 원인 해결 화면
    버튼이 비활성화되어 있습니다. 툴팁에 내 역할에 ‘’ 권한이 없습니다.라고 표시됩니다. 사용자의 어떤 역할도 해당 권한을 보유하지 않습니다. 사용자가 보유한 역할에 해당 권한을 추가하십시오. 권한은 역할 사전에서 영역별로 묶여 있습니다. 역할, 구성원
    툴팁에 ‘’에는 ‘’ 권한도 필요하지만, 내 역할에는 없습니다.라고 표시됩니다. 해당 권한은 다른 권한을 필요로 합니다(카탈로그의 requires 목록). 두 권한을 모두 부여하십시오. 필요한 권한도 부여될 때까지 역할 저장은 "a capability is missing one it needs"로 거부됩니다. 역할
    툴팁에 ‘’은(는) 여기에서 사용할 수 없습니다: 담당 기관 범위에 포함되지 않습니다.라고 표시됩니다. 사용자가 해당 권한을 보유하고 있으나, 그 작업이 할당된 시설 밖의 시설을 대상으로 합니다(또는 모든 시설에 걸칩니다). 사용자의 시설 할당을 변경하십시오. 구성원
    구성 저장이 저장되지 않음: “” 권한이 필요합니다. 관리자가 구성 → 직원 → 역할 사전에서 부여할 수 있습니다.라는 메시지와 함께 실패합니다. 사용자에게 해당 화면의 config:...:manage 권한이 없습니다(코드 CONFIG_NOT_PERMITTED). 명시된 권한을 사용자의 역할에 부여하십시오. 역할
    역할 저장이 Not saved: no role could manage roles afterwards.라는 메시지와 함께 실패합니다. 이 변경으로 config:roles:manage를 보유한 할당 가능한 역할이 하나도 남지 않게 됩니다. 먼저 다른 할당 가능한 역할에 역할 관리를 부여한 다음 저장하십시오. 역할
    역할 또는 직원 저장이 changing the clinical mismatch rules and approving the AI instructions are separate duties 메시지와 함께 실패합니다. 한 사람(또는 한 역할)이 config:clinical-mismatch-rules:manage와 config:ai-prompt:approve를 모두 보유할 수 없습니다(코드 SEPARATION_OF_DUTIES). 두 권한을 서로 다른 사람이 보유한 두 역할로 나누십시오. 역할, 구성원
    역할 저장이 this role is managed by ForMedrixAI 메시지와 함께 실패합니다. Superadmin 역할은 병원에서 변경할 수 없습니다. 방법이 없습니다. 다른 역할을 사용하십시오. 역할
    사용자가 화면을 열면 이 화면에 대한 접근 권한이 없습니다가 표시됩니다. 로그인 후 홈 페이지에는 None of your roles gives you access to a screen yet.라고 표시됩니다. 역할에 screen:<name>:open 권한이 없으므로 홈에 타일이 표시되지 않고 라우트가 해당 주소를 거부합니다. 역할에 화면 권한을 추가하십시오. 역할
    사용자가 자신의 편집을 승인할 수 없습니다: 이 텍스트를 편집하셨으므로 승인할 수 없습니다. AI 지침에서는 자기 승인이 거부됩니다(코드 SELF_APPROVAL). config:ai-prompt:approve를 보유한 다른 사람이 승인하도록 하십시오. AI 지침
    내보내기 버튼이 작동하지 않거나, 내보내기 화면에 이 보고서를 내보낼 권한이 없습니다.라고 표시됩니다. 각 내보내기에는 고유한 권한이 있으며(예: audit:audit-log:export), 서버는 다운로드 시 이를 다시 확인합니다. 버튼 툴팁에 명시된 내보내기 권한을 부여하십시오. 역할, 내 내보내기

    # 인쇄되지 않는 라벨과 보고서

    증상 가능한 원인 해결 화면
    라벨이 브라우저 인쇄 창으로 전송되고 메시지에 라벨 프린터가 연결되어 있지 않아 이 라벨이 브라우저 인쇄 창으로 전송되었습니다. 이 컴퓨터에서 QZ Tray가 실행 중인지 확인하세요.라고 표시됩니다. 해당 컴퓨터에서 QZ Tray 서비스가 실행 중이 아니거나 접근할 수 없습니다. 컴퓨터에서 QZ Tray를 시작한 다음 다시 인쇄하십시오. 프린터 프로필, 인쇄 설정
    Label did not print: is out of labels / is out of ribbon / the print head is open / could not be reached. 프린터가 해당 상태를 보고했습니다(코드 PAPER_OUT, RIBBON_OUT, HEAD_OPEN, PRINTER_UNREACHABLE). 프린터를 수리한 다음 라벨을 다시 시도하십시오. 라벨은 저절로 다시 시도되지 않으므로 두 번 인쇄될 수 없습니다. 인쇄 대기열
    ...did not print: rejected the label layout 또는 its barcode failed GS1 validation. This is a PathScribe problem; please report it. 라벨의 내용이 거부되었습니다(MALFORMED_ZPL, INVALID_GS1). 다시 시도해도 해결되지 않습니다. 시각과 라벨의 레이아웃을 함께 ForMedrixAI 지원팀에 보고하십시오. 라벨 디자이너
    보고서 인쇄 작업이 "Network printing needs the PathScribe site agent."와 함께 실패로 표시됩니다. 브라우저에서 네트워크 프린터로 보고서를 보냈으나 브라우저는 해당 프린터에 접근할 수 없습니다(NEEDS_SITE_AGENT). 검사실의 인쇄를 사이트 에이전트 프린터로 라우팅하십시오. 사이트 에이전트, 인쇄 대상 라우팅 규칙
    인쇄가 "작동"하는 것처럼 보이지만 데모에서 아무것도 출력되지 않습니다. 데모는 인쇄를 전송하지 않고 기록합니다. 시뮬레이션 인쇄 기록을 확인하십시오. 시뮬레이션 인쇄 기록

    # 시스템 오류 코드 색인

    홈 › 관리자 가이드 › 부록 › 시스템 오류 코드 색인

    상태: 구현됨

    이 색인이 다루는 범위. 관리자가 화면에서 볼 수 있거나, 오류 로그에서 읽거나, 계약서에서 찾을 수 있는 소스의 대문자 코드입니다. 각 행은 코드가 나타나는 화면, 의미, 조치를 제공합니다. 두 번째 열에 명시된 계약서는 docs/architecture/에 있습니다. 어떤 계약서에도 코드가 없는 경우 해당 행에는 서비스 파일이 명시됩니다.

    코드가 화면에 도달하는 방식. API 클라이언트는 실패한 모든 호출에 짧은 고정 코드를 부여하며, 서버의 메시지 텍스트에 환자 이름이 포함될 수 있으므로 이를 사용하지 않습니다. 서버 코드가 대문자, 숫자, 밑줄로 이루어져 있고 길이가 2~40자이며 문자로 시작하면 서버 코드를 사용합니다. 그렇지 않으면 코드는 HTTP 상태에서 가져옵니다.

    상태 코드
    401 SIGNED_OUT
    403 NOT_PERMITTED
    404 NOT_FOUND
    409 CONFLICT
    400, 422 INVALID
    429 TOO_MANY_REQUESTS
    그 외 모든 경우 UNAVAILABLE

    소문자 사유도 있습니다(예: 로그인 사유 not_provisioned와 inactive, 서버의 capability_refused, support_access_disabled, support_access_not_approved). 이들은 대문자 코드가 아니므로 이 색인이 아니라 위의 매트릭스와 지원 접근 화면에 있습니다.

    # 서버 기반의 모든 화면에 표시될 수 있는 코드

    오류 코드 표시되는 위치 의미 조치
    SIGNED_OUT API 서버를 호출하는 모든 화면. 계약서: HTTP_SERVICES_PATTERN.md 4절, src/services/apiServer/apiHttpClient.ts. 서버가 401로 응답했습니다. 로그인이 종료되었거나 토큰이 수락되지 않았습니다. 다시 로그인하십시오. 로그인 직후 다시 발생하면 ForMedrixAI 지원팀에 알리십시오.
    NOT_PERMITTED 서버 기반의 모든 화면. 계약서: HTTP_SERVICES_PATTERN.md, AUTHORIZATION_API.md. 서버가 403으로 응답했습니다. 권한이 없거나 사용자의 시설 범위 밖입니다. 비활성화된 버튼에 관한 매트릭스 행을 참조하십시오. 시스템 로그에서 Capability refused를 검색하십시오.
    NOT_FOUND 서버 기반의 모든 화면. 계약서: HTTP_SERVICES_PATTERN.md. 레코드가 더 이상 존재하지 않습니다. 예를 들어 다른 사람이 삭제하거나 폐기했습니다. 새로 고친 다음 다시 여십시오.
    CONFLICT 버전이 있는 저장이 있는 모든 화면. 계약서: HTTP_SERVICES_PATTERN.md(버전이 있는 저장). 서버가 409로 응답했습니다. 레코드를 읽은 이후 변경되었습니다. 케이스의 경우 서버는 보유한 버전도 반환합니다. 새로 고치고 변경을 다시 적용하십시오.
    INVALID 서버 기반의 모든 저장. 계약서: HTTP_SERVICES_PATTERN.md. 서버가 400 또는 422로 응답했습니다. 값을 거부했습니다. 양식의 입력값을 확인한 다음 다시 저장하십시오.
    TOO_MANY_REQUESTS 서버 기반의 모든 화면. 계약서: HTTP_SERVICES_PATTERN.md, STAFF_ADMIN_API.md. 서버가 429로 응답했습니다. 속도 제한에 도달했습니다. 잠시 기다린 다음 다시 시도하십시오. 반복되는 경우는 ForMedrixAI 지원팀으로 보내십시오.
    TIMED_OUT 서버 기반의 모든 화면, 내보내기 목록. 계약서: HTTP_SERVICES_PATTERN.md, ASYNC_EXPORT_API.md 4절. 호출이 30초(클라이언트의 기본값) 이내에 응답을 받지 못했습니다. 내보내기 빌드의 경우 빌드가 30분 후에 중단되었습니다. 다시 시도하십시오. 내보내기의 경우 필터를 좁히십시오.
    UNAVAILABLE 서버 기반의 모든 화면, 예를 들어 워크스테이션 목록, 사이트 에이전트 목록, 엔진 패널, 서버 작업. 계약서: HTTP_SERVICES_PATTERN.md. 서버에 접근할 수 없었거나, 그 밖의 상태로 응답했거나, JSON 객체가 아닌 응답을 보냈습니다. 네트워크와 API 서버를 확인하십시오. 다시 시도하십시오.
    NOT_SUPPORTED 서버 배포에서의 데모 전용 작업. 계약서: HTTP_SERVICES_PATTERN.md, src/services/apiServer/httpServiceExtras.ts. 해당 메서드는 데모(데모 데이터 시드)에만 존재합니다. 서버 버전은 호출하지 않습니다. 조치는 필요하지 않습니다. 서버 배포에서는 정상입니다.

    # 시작 구성

    이 코드들은 전체 페이지 PathScribe를 시작할 수 없습니다: 구성을 수정해야 합니다 화면에 표시됩니다. 수정될 때까지 PathScribe는 시작되지 않습니다. 설정과 규칙은 RUNTIME_CONFIG.md 3절에 있습니다. 코드는 src/services/runtimeConfig/runtimeSettings.ts입니다.

    오류 코드 표시되는 위치 의미 조치
    UNREADABLE 시작 화면. config.json이 올바른 JSON이 아닙니다. 파일을 수정하십시오.
    NOT_AN_OBJECT 시작 화면. config.json은 설정과 값의 목록(JSON 객체)이어야 합니다. 파일을 수정하십시오.
    UNKNOWN_SETTING 시작 화면. 이름이 PathScribe가 아는 설정이 아니거나, 빌드 전용 이름입니다. RUNTIME_CONFIG.md와 철자를 대조하십시오.
    NOT_TEXT 시작 화면. 값은 텍스트, 숫자, 또는 true나 false여야 합니다. 값을 수정하십시오.
    TOO_LONG 시작 화면. 값이 2,000자보다 깁니다. 줄이십시오.
    INVALID_URL 시작 화면. 값은 웹 주소이거나 /로 시작하는 이 사이트의 경로여야 하며, 사용자 이름이나 비밀번호가 포함되어서는 안 됩니다. 주소를 수정하십시오.
    NOT_HTTPS 시작 화면. 주소는 https를 사용해야 합니다. 일반 http는 개발 빌드에서 이 컴퓨터로 향하는 경우에만 허용됩니다. https 주소를 사용하십시오.
    NOT_THIS_SITE 시작 화면. 프록시 경로가 다른 사이트로 연결됩니다(예: //host). 이 사이트의 경로 또는 https 주소를 사용하십시오.
    API_SERVER_REQUIRED 시작 화면. 서버 빌드에는 PathScribe 서버의 주소가 필요한데 설정되어 있지 않습니다. API 주소를 설정하십시오.
    SSO_REQUIRED 시작 화면. 서버 빌드는 ID 제공자를 통해서만 로그인하므로 VITE_AUTH_MODE는 sso여야 합니다. 이를 설정하고 제공자의 설정을 입력하십시오.
    API_SERVER_IN_DEMO_BUILD 시작 화면. 데모 빌드는 실제 서버와 통신하지 않습니다. 서버 빌드를 설치하십시오.
    NOT_IN_DEMO_BUILD 시작 화면. 데모 빌드는 허브, 렌더러, 인터페이스 수신기 또는 서버 작업 설정을 사용할 수 없으며 운영 환경이 될 수 없습니다. 서버 빌드를 설치하십시오.
    ADDRESS_NOT_FROM_SERVER 시작 화면, "from the PathScribe server's /api/config"로 표시됨. 사이트의 보안 정책이 config.json에서 만들어지므로 서버는 주소를 설정할 수 없습니다. 주소를 config.json에 넣으십시오.
    NOT_FROM_SERVER 시작 화면, "from the PathScribe server's /api/config"로 표시됨. 이 설정(로그인, 인스턴스 역할, 서버가 실행하는 작업)은 config.json 또는 빌드만 설정할 수 있습니다. 설정을 config.json으로 옮기십시오.

    # 감사 로그 검증 가이드

    홈 › 관리자 가이드 › 부록 › 감사 로그 검증 가이드

    상태: 부분 구현. 기록, 검색, 내보내기는 구현되어 있습니다. 주 감사 로그의 변조 증거 기능과 보존 기간에 따른 자동 삭제는 구현되어 있지 않습니다.

    이 가이드의 대상. 무엇이 변경되었는지, 누가 변경했는지, 언제 변경했는지를 감사자나 조사관에게 보여 주어야 하는 관리자 또는 ForMedrixAI 서비스 엔지니어입니다. 현재 존재하는 기능만 사용합니다.

    # 기록되는 내용

    각 감사 항목에는 다음이 들어 있습니다. id, 시각(UTC로 저장), 유형(AI, 사용자 또는 시스템), 이벤트 이름, 영어로 된 상세 문장, 작업한 사용자의 표시 이름, 해당하는 경우 케이스 접수번호, 해당하는 경우 AI 신뢰도, 코드가 제공하는 경우 시설 id, 작업이 수행된 스캔 스테이션. 스테이션 id는 감사 서비스가 기록하는 모든 항목에 자동으로 추가됩니다.

    로그에 남는 내용은 다음과 같습니다.

    • 높은 위험도 권한의 모든 확인(허용 또는 거부). 이벤트는 권한 허용됨 또는 권한 거부됨입니다. 상세에는 권한 키, 해당 권한을 부여한 역할 또는 거부된 사유, 사용자의 세션 역할, 시설이 기재됩니다. 어떤 권한이 높은 위험도인지는 권한 카탈로그에 표시되어 있습니다. 구성 화면의 저장도 이러한 확인 중 하나입니다.
    • 역할 및 직원 변경. 역할 권한 변경됨은 역할에 대해 부여된 권한과 제거된 권한을 나열합니다. 직원 접근 변경됨은 사용자의 역할, 시설, 소아 접근, 오케스트레이션 접근 또는 테넌트 간 QA 접근의 변경을 변경 전 값과 변경 후 값으로 기록합니다. 직원 자격 증명 변경됨은 자격 증명 편집을 기록합니다.
    • 로그인 이벤트. 로그인됨, 로그인 실패(5회 중 n번째 시도), 로그인 잠김, 로그인 거부됨, SSO 계정 연결됨, SSO 계정 연결 해제됨, SSO 로그인 거부됨. 로그에는 입력한 내용이 기록되지 않습니다.
    • 일부 설정의 이름 있는 변경 이벤트. 예를 들어 AI_VENDOR_POLICY_CHANGED, CLINICAL_MISMATCH_RULE_CHANGED, AI_PROMPT_EDITED, AI_PROMPT_APPROVED, FEEDBACK_SETTINGS_CHANGED, RECALL_SETTINGS_CHANGED, QA_TREND_POLICY_CHANGED, CODE_SYSTEM_POLICY_CHANGED, PEER_REVIEW_GATE_CHANGED, 템플릿 검토 설정 변경됨, 장기 지도 색상 변경됨, 서명 권한 국가 프로필 변경됨, 그리고 네 가지 서명 권한 시설 재정의 이벤트(추가, 변경, 제거, 사유 갱신)가 있습니다. 시설 재정의 이벤트에는 변경된 각 플래그의 변경 전 값과 변경 후 값, 그리고 관리자의 사유 또는 "사유: 제공되지 않음"이 기재됩니다.
    • 인쇄와 내보내기. DOCUMENT_PRINTED, DOCUMENT_REPRINTED, DOCUMENT_RENDERED, DOCUMENT_EXPORTED, DOCUMENT_FAXED: 누가, 접수번호, 대상, 상태, 그리고 내보내기의 경우 행 수가 기록됩니다.
    • 케이스 이벤트. 예를 들어 종합 보고 생성, 필드 갱신, 최종 확정, 프로토콜 선택, 드리프트 감지 및 수정, 청구 정정, 환자 관리(mpi.*)가 있습니다.
    • 시스템 행위자에 의한 자동 작업.

    기록을 읽을 때 중요한 제한이 두 가지 있습니다.

    1. 권한 항목은 어떤 사용자가 권한을 사용했다는 것과 허용되었는지 여부를 보여 줍니다. 대부분의 설정에서는 이전 값과 새 값이 표시되지 않습니다. 위에 이름이 나온 이벤트와 몇 가지 다른 이벤트만 변경 내용 자체를 담고 있습니다.
    2. Superadmin 세션이 다른 조직에서 작업하는 동안 이루어진 변경은 그 조직의 지원 접근 기록에도 기록됩니다.

    상세 텍스트는 설계상 영어입니다. 감사 기록은 인터페이스 텍스트가 아니라 컴플라이언스 산출물이므로, 상세는 제품의 모든 언어와 내보낸 파일에서 영어 그대로 유지됩니다. 영어 이벤트 이름이나 권한 키로 검색하십시오.

    # 설정 변경을 찾는 방법

    1. 시스템 로그의 감사 로그 탭을 엽니다.
    2. 기간을 설정합니다. 기본값은 최근 7일이며, 더 오래된 변경은 사용자 지정 기간을 선택합니다. 기간 밖의 항목은 숨겨져 있을 뿐 없어진 것이 아닙니다.
    3. 검색에 확인하려는 화면의 권한 키를 입력합니다. 모든 구성 화면의 변경 권한은 이 가이드의 권한 부분에 이름이 나와 있습니다(예를 들어 데이터 보존은 config:retention-policy:manage). 검색은 상세 텍스트와 일치하므로 권한 허용됨 항목을 찾습니다.
    4. 누가 언제 했는지는 사용자 열과 타임스탬프 열에서 확인합니다. 상세에는 해당 권한을 부여한 역할이 기재됩니다.
    5. 해당 화면에 이름 있는 변경 이벤트가 있으면(위 목록 참조) 그 이벤트 이름으로도 검색합니다. 그 이벤트에는 권한 확인뿐 아니라 변경 내용 자체가 들어 있습니다.
    6. 불필요한 항목을 제외하려면 유형 필을 사용합니다(사용자는 사람의 작업을 표시합니다).
    7. 거부된 항목만 보려면 Capability refused를 검색합니다.

    권한 허용됨이라고 표시된 항목은 그 사용자가 변경할 수 있는 권한을 가지고 있었고 변경이 시도되었음을 보여 줍니다. 그것만으로 어떤 값이 저장되었는지가 증명되지는 않습니다. 자체 변경 이벤트가 없는 설정은 화면의 현재 값과 비교하고, 검사실이 구성 내보내기를 보관하고 있다면 그것과도 비교하십시오(아래 내보내기 참조).

    # 권한을 누가 변경했는지 확인하는 방법

    1. 감사 로그 탭에서 Role capabilities changed를 검색합니다. 각 항목은 Role "<name>": granted <keys>; removed <keys>. 형식입니다. 사용자 열은 역할을 저장한 사용자입니다.
    2. 누구에게 역할이 부여되었거나 박탈되었는지 보려면 Staff access changed를 검색합니다. 상세에는 각 변경이 변경 전 값과 변경 후 값으로 나열됩니다(역할, 시설, 소아 접근, 오케스트레이션 접근, 테넌트 간 QA 접근).
    3. 자격 증명 편집을 보려면 Staff credentials changed를 검색합니다.
    4. 사용자가 권한을 실제로 사용했는지 보려면 권한 키를 검색하고 권한 허용됨 및 권한 거부됨 항목을 읽습니다.
    5. 현재 누가 무엇을 할 수 있는지 나열하려면 역할과 구성원을 사용합니다. 로그는 이력을 보여 주고, 이 화면들은 현재 상태를 보여 줍니다.
    6. 병원이 변경할 수 없는 역할에 대해: Superadmin 역할의 변경은 병원에서는 거부되므로 그러한 항목은 나타나지 않습니다. Superadmin은 ForMedrixAI 지원 직원이 보유하며 병원의 직원 디렉터리 밖에서 부여됩니다.

    역할 저장은, 역할을 관리할 수 있는 역할이 하나도 남지 않게 되는 경우, 직무 분리 쌍을 깨뜨리는 경우, 또는 필수 권한 없이 권한을 부여하는 경우에도 아무것도 기록되기 전에 거부됩니다. 거부된 저장은 역할 권한 변경됨 항목을 기록하지 않습니다.

    # 기록 무결성과 보존이 작동하는 방식

    추가 전용. 감사 서비스에는 항목을 갱신하거나 삭제하는 호출이 없으며, 새 항목을 쓰고 읽을 수만 있습니다. 서버 계약서(STAFF_ADMIN_API.md 1절, AUTHORIZATION_API.md)는 감사 테이블이 추가 전용일 것을 요구합니다. 갱신 또는 삭제 호출이 없고, 애플리케이션의 데이터베이스 로그인에 그러한 권한이 없습니다. 기록에 허용되는 유일한 변경은 해결된 오류이며, 이는 메시지를 덮어쓰는 것이 아니라 오류 항목에 누가 언제 해결했는지로 기록됩니다.

    시각과 행위자를 정하는 주체. API 서버를 사용하면 서버가 시각을 정하고, 행위 사용자는 베어러 토큰에서 가져옵니다. 브라우저는 이벤트만 보내므로 사용자가 표시되는 이름을 선택할 수 없습니다. 데모에서는 브라우저가 이를 정합니다.

    고유 id. 모든 항목에는 고유 id가 부여됩니다. 서버의 테이블도 고유성을 강제할 것으로 예상됩니다.

    변조 증거: 주 감사 로그에는 없습니다. 주 감사 로그는 해시 체인으로 연결되어 있지도, 서명되어 있지도 않습니다. 시스템 로그 화면의 어떤 것도 데이터베이스에 직접 접근할 수 있는 사람이 항목을 변경하지 않았음을 증명하지 못하며, 이를 위한 "검증" 버튼도 없습니다. 무결성은 위의 추가 전용 규칙과 데이터베이스 권한에 의존합니다. 해시 체인으로 연결된 유일한 기록은 지원 접근 감사입니다(아래 참조). 감사자가 주 로그에 대해 암호학적 변조 증거를 요구하는 경우 ForMedrixAI에 알리십시오. 이 기능은 구현되어 있지 않습니다.

    보존. 감사 로그의 보관 기간은 데이터 보존의 설정입니다. 감사 로그 필드이며 일 단위로 90에서 3650까지, 기본값은 365입니다. 화면에는 변경 사항이 "다음 삭제 주기에 적용됩니다"라고 표시됩니다. 이 설정을 읽는 삭제 작업이 아직 없으므로(PS-345) 현재는 이 설정으로 삭제되는 것이 없습니다. 이 숫자는 강제되는 정책이 아니라 기록된 정책으로 취급하십시오. 각 내보내기의 기록(누가, 무엇을, 언제, 행 수, 파일 해시)은 감사 로그의 보존 기간에 따라 보관됩니다.

    내보내기는 작업용 사본입니다. 내보낸 CSV는 화면에 있던 내용의 사본입니다. 내보내기의 기록은 감사 항목입니다.

    # 내보내는 방법

    1. 필요한 탭에서 먼저 필터를 설정합니다. 내보내기는 로그 전체가 아니라 필터가 남긴 행을 대상으로 합니다.
    2. CSV 내보내기를 선택합니다. 해당 탭의 내보내기 권한이 있는 사용자가 아니면 버튼이 회색으로 비활성화되고 툴팁에 권한 이름이 표시됩니다(위의 권한 부분 참조).
    3. 서비스는 파일을 만들기 전에 권한을 확인합니다. 거부되면 아무것도 만들어지지 않습니다.
    4. API 서버를 사용하면 내보내기는 서버가 만듭니다(내 내보내기 참조). 파일은 기본 7일(1~30일) 동안 보관되는 작업용 사본이며, 한 사용자가 열어 둘 수 있는 내보내기는 3개이고, 1,000,000행을 초과하면 거부됩니다. 데모에서는 브라우저가 파일을 만들어 즉시 다운로드합니다.
    5. 파일 이름은 pathscribe-audit-log-<date>.csv 형식입니다. 처음 몇 줄은 보고서 이름, 요청한 사용자, 사용한 필터, 행 수를 알리는 머리글입니다. 그다음 열은 ID, 타임스탬프, 유형, 이벤트, 상세, 처리자, 접수번호, AI 신뢰도입니다. =, +, -, @로 시작하는 셀은 스프레드시트가 수식으로 실행하지 않도록 무력화됩니다.
    6. 모든 내보내기는 사용자, 파일 이름, 형식, 행 수가 담긴 DOCUMENT_EXPORTED 항목을 기록합니다. 로그를 누가 내보냈는지 보려면 DOCUMENT_EXPORTED를 검색합니다.
    7. CSV에는 시설 id와 스테이션 id가 들어 있지 않습니다. 조사관에게 필요하면 ForMedrixAI 서비스에 알리십시오. 서버에 이 정보가 있습니다.
    8. 다른 탭도 같은 방식으로 내보내며, 각각 고유한 권한과 고유한 열이 있습니다. 오류 로그(ID, 타임스탬프, 심각도, 코드, 메시지, 소스, 접수번호, 해결됨), 품질보증(ID, 그룹, 날짜, 케이스, 검체, 상세, 상태, 사용자), 인터페이스 로그, 재무 청구 로그입니다.

    # 지원 접근 감사가 맞물리는 방식

    ForMedrixAI 지원 담당자가 귀하의 데이터에 접근한 내용은 주 감사 로그와는 별도의 자체 기록 흐름에 기록되며, 이 기록은 귀하의 조직에 속합니다. 이는 지원 접근에 설명되어 있습니다.

    • 기록하는 내용. 정책 변경, 요청·승인·거부·만료·조기 종료·취소, 거부된 열기, 케이스 열기와 편집, 귀하의 케이스를 노출한 모든 목록·검색·보고서(케이스 id 포함), 검색 조건의 이름(값은 기록하지 않음), 이 감사의 내보내기. 지원 담당자 본인의 내보내기와 구성 변경도 여기에(supportExport 및 supportConfigChange로) 기록되며, 주 감사 로그에도 기록됩니다.
    • 항목은 절대 제거되지 않습니다. 각 항목에는 순번, 시각, 행위자, 티켓, 작업, 케이스 id, 영어로 된 환자 정보 없는 상세가 들어 있습니다.
    • 해시 체인으로 연결되어 있습니다. 각 항목은 자신의 필드와 이전 항목의 해시에 대한 SHA-256을 가지며, 첫 항목은 64개의 0에서 시작합니다. 항목이 변경, 제거 또는 순서가 바뀌면 체인이 끊어집니다. 화면에는 기록 온전함(N개 항목) 또는 N번째 항목에서 기록 변경됨이 표시되며, JSON 내보내기에는 체인 검사 결과가 들어 있습니다.
    • 검증하는 방법. 지원 접근을 열고 감사 패널의 체인 줄을 읽은 다음, 독립적인 검사를 위해 JSON을 내보냅니다. config:support-audit:view가 필요합니다.
    • 내보내기 형식. CSV, JSON, PDF이며 열은 타임스탬프, 지원 담당자 이름, 발신 IP, 발신 국가, 티켓 ID, 수행한 작업, 케이스 ID, 상세입니다.
    • 제한. 발신 IP와 국가는 서버가 요청에서 가져와야만 사실대로 기록할 수 있으므로 데모에서는 비워 둡니다. 자체 추가 전용 테이블에 테넌트별로 분리하여 저장하는 것은 서버 작업입니다(PS-358).

    이것은 제품에서 변조 증거 기능이 내장된 유일한 기록입니다. 지원 접근만 대상으로 하며 주 감사 로그는 대상이 아닙니다.

    # 간단한 검증 절차

    표본으로 선정한 기간을 정기적으로 검토할 때는 다음 단계를 따르십시오.

    1. 감사 로그 기간을 해당 기간으로 설정합니다. 바닥글의 개수("{총}개 중 {표시}개 이벤트 표시 중")를 기록합니다.
    2. Role capabilities changed, Staff access changed, Capability refused를 검색하여 각 항목을 읽습니다.
    3. 로그인 문제를 확인하려면 Sign-in locked와 Sign-in refused를 검색합니다.
    4. 누가 데이터를 반출했는지 보려면 DOCUMENT_EXPORTED를 검색합니다.
    5. 오류 로그 탭을 열고 미해결만으로 필터링하여 중요한 항목이 해결되지 않은 채 남아 있지 않은지 확인합니다.
    6. 지원 접근을 열어 체인 줄이 온전함으로 표시되는지 확인하고 해당 기간의 항목을 읽습니다.
    7. 해당 기간의 감사 로그 CSV를 내보내 검토 메모와 함께 파일을 보관합니다. 이 내보내기 자체도 기록됩니다.
