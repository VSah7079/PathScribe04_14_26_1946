# Gap register (audit of Oct 2026, Appendix A, and the fixes of Batches 649 to 652)

One table of every gap the October 2026 code audit found (Appendix A of the disclosure, items A.1 to A.10), with where each stands. The audit read the code, not the product descriptions, so every status here is checked against the code or the batch documents named in the "Where" column, not assumed. First written in Batch 652 and finalised after Batches 650 to 652 were complete: every former "pending verification" row was checked against the named files (present, called from the screen or service it names, covered by a test file) and the full suite passed (1,767 files, tsc clean).

**Status words**

- **Fixed in Batch N**: changed in code or in the document, with a test or a checked text. A row with a Fixed label and a leftover (for example a label fixed but the real data Planned) is counted once, as Fixed; the leftover is named in the Note and in `KNOWN_GAPS.md`.
- **Open - product decision**: a person has to choose (Pete, a clinical lead, counsel). Nothing is blocked technically.
- **Planned - needs server**: waits for the API server, the interface engine or another server-side part that does not exist yet.
- **Planned - other**: waits for something that is not the server: a licence, a vendor SDK or specification, hardware, a clinical or compliance review.

Rows keep their Appendix A number in the first column. Rows "F-" are fixes of Batches 649 to 652 that Appendix A did not list as separate items. Related documents: `KNOWN_GAPS.md` (running list with owners), `GUIDE_UPDATES.md` (what changed for each audience), `FEATURE_OVERVIEW.md` (status per feature).
