# Chapter 9 open questions (Appendices: Troubleshooting and Audit Log Verification, Glossary)

Each item needs Pete's decision or a ForMedrixAI answer, or records a place where the docs and the source disagree. The chapter follows the source.

- **No tamper-evidence on the main audit log.** Only the Support Access audit is hash-chained. The main audit log is append-only by contract and by service design, but has no hash chain, signature or verify button. The chapter says so plainly. Decide whether a chain or periodic signed digest is wanted for the main log (an inspector may ask).
- **Retention does not purge.** The Data Retention screen says a change "takes effect at next purge cycle" and offers Audit Logs 90 to 3650 days (default 365), but no purge job reads it (PS-345). The screen's own wording implies a purge exists; consider changing it. `docs/product` and chapter 1 already say it is not enforced.
- **Chapter 1 line 322 overstates configuration auditing.** It says configuration changes are audited "with before and after values for sensitive ones". Today only some settings have their own change event with values (AI vendor policy, signing-authority overrides, role capabilities, staff access). Most high-risk settings write only a **Capability allowed** entry that names the capability and person, not the new value. Chapter 9 says this. Chapter 1 may need the same wording.
- **Contract route mismatch.** `STAFF_ADMIN_API.md` section 1 lists `GET /api/audit/logs` and `GET /api/audit/errors`; `httpAuditService.ts` calls `POST /api/auditlog/audit/get-audit-logs` and `get-error-logs` (the Batch 617 route style). The contract table is stale.
- **Stale README bullet.** `src/services/supportAccess/README.md` ("What waits for the API server") says PDF export and copying a support agent's exports and configuration changes into the hospital's stream are not done. The code does both (`exportAuditPdf` in the Support Access screen; `reportSupportActivity` in `guardConfigWrites.ts`; Batch 604). The chapter follows the code.
- **`CASE_CHANGED` is in `src/services/apiServer/README.md` as an example server code but appears nowhere in source or contracts.** Not indexed.
- **Codes with no contract doc.** Many screen-level refusals (code import, workstations, BI feed, Assist LIS, code systems, protocol upload, `BUILD_FAILED`) are defined in service files, not in any `docs/architecture/*_API.md`. The index cites the service file. Consider adding them to the contracts so the API server returns the same codes.
- **`UPSTREAM_KEY_INVALID`** (502, in `TERMINOLOGY_PROXY_API.md`) is a server-side code with no use in the browser source, so it is not indexed. Confirm whether the browser should show it.
- **`EXPIRED` has two meanings** (an export file past its keeping period; a site agent job not started in time). One row explains both.
- **Country Signing Rules codes left out.** `LAST_COUNTRY`, `NO_CHANGES` and `SAVE_FAILED` belong to a platform-only screen (`platform:signing-rules:manage`), so they are not in the customer-facing index. Add them to the internal edition if wanted.
- **Facility and station are recorded but not shown.** Audit entries carry `facilityId` and `stationId`, but System Logs has no column for them and the CSV omits them. An inspector may expect them. Decide whether to add columns.
- **User filter is Superadmin-only.** The Audit Log user drop-down shows only in a Superadmin session ("to prevent bias in validation studies"). An administrator must search by name instead. Confirm that is intended.
- **Pathologist scoping is code only by default.** The page narrows a Pathologist to case events plus their own entries and shows a notice, but the Pathologist role is not seeded `screen:audit-log:open`. It applies only if a hospital grants the screen.
- **Audit tab date range default is 7 days** with no way to load older entries except Custom Range. A first-time administrator may think older entries do not exist. The guide says so.
- **Glossary scope.** 196 terms. Generic words (batch, hold, section, panel, pool, client, barcode, material, global) were left out because the builder links the first use in every section and would mark ordinary prose. Add any back if wanted. CSMS and SCU were left out because the repo does not define them. FAD is defined from its use beside PAD ("final anatomical diagnosis") and should be confirmed.
- **Screenshot ids.** `screen-audit-log` is a listed capture id; `screen-audit-log-errors` is new and will show in `MISSING_CAPTURES.md`.
