# Findings while drafting the Workstations, Margin Exception Review, Add-On Orders and WSI Viewer articles (Batch 666)

Found by reading the screens against the code. Nothing was changed in source. Each row is a decision or a defect for the product owner. The articles describe the behaviour as it is today and should be updated once these are settled.

| # | Where | Finding |
|---|---|---|
| 1 | Microtomy, Embedding, Slide Distribution | **Back** goes to `/worklist`, not to the Pathology Workspace the screens are opened from. |
| 2 | Microtomy, decant | On a decant, the slide comment button and the Reprint reason do nothing (`handleAddStainComment` and `handleReprint` return at once unless the work item is a block), although both controls are shown. Block comments, alert badges and Block exhausted are blocks only (correctly hidden). — Fixed in Batch 669. |
| 3 | Microtomy, Block exhausted | The flag is placed on the first slide of the block that has no open exception, and the e-mail goes to that slide's `orderedByPathologistId`. If that slide was not placed through Add-On Orders (an original H&E, say) nobody is e-mailed, and the Add-On Orders Order Tracking list shows only slides with an ordering pathologist, so the pathologist has no screen on which to answer. Cutting then stays blocked. — Fixed in Batch 669: with no ordering pathologist (or none with an e-mail address) the notice goes to the Supervisor / Accessioning Desk (Lab Director and Accessioner roles), and a slide with an open exception is listed in Order Tracking so it can be answered. |
| 4 | Microtomy | On-Demand **Print/Etch Next** and per-row **Print** ignore the result of the print: a refusal because the block is flagged exhausted shows only the banner, and "The print couldn't be started" is never shown. A printer failure shows only as Failed in the grid. The batch window does show the messages. — Fixed in Batch 669 for **Print/Etch Next** (and foot pedal 2): the refusal or printer message is shown on screen. The per-row **Print** already showed the messages, through the progress window. |
| 5 | Microtomy, decant | **Accept suggestion** adds the suggested slides every time it is pressed, with no check for ones already added. The README also mentions a per-slide preparation-method selector and a Pap / Diff-Quik / H&E toggle that the panel does not have. — Fixed in Batch 669 (dedupe; the README claim about a per-slide selector and a Pap / Diff-Quik / H&E toggle was removed). |
| 6 | Microtomy, Remove and Reprint | Choosing a reason in the list acts at once (there is no confirm button), unlike the Embedding and Slide Distribution reprint windows, where a reason is chosen and then Reprint is pressed (Batch 401 and 402 changed those two only). — Fixed in Batch 669 by a quick Undo toast (Pete's ruling) rather than a confirm button. |
| 7 | Microtomy and Batch Management | Two print paths remain (already listed in the Microtomy README): a block scanned at a Microtomy / Sectioning station is labelled by the global scan tracker, and this screen then skips the second print through a "label already produced" memory. The Label Preview is a drawing, and the configured label layout is not yet used by the label itself (Microtomy README). |
| 8 | Embedding, Slide Distribution, Add-On Orders | Saving a change only logs a failure to the console. Unlike Microtomy (retries, "Not saved" message and reload), these three show the change on screen as if it were saved. — Fixed in Batch 669. |
| 9 | Embedding | **Observed count** starts filled with the grossing count, so one click on Confirm records "no discrepancy" without a count. Foot pedal 1 confirms the grossing count by design, so it can never record a mismatch. Decide whether the box should start empty. |
| 10 | Embedding | A discrepancy flag has no confirmation, cannot be cleared, and does not stop **Confirm** (the README says it halts the block). **Last flagged ... (by X)** shows the user ID, not the name. The status list on the left and the DOB in the identity bar show stored values (English status text, unformatted date). — Fixed in Batch 669. |
| 11 | Embedding | A mismatch or flag raises a Tissue Discrepancy item with no message on screen, and a failed raise is only logged. — Fixed in Batch 669. |
| 12 | Slide Distribution | An unresolved scan is always logged as "Unreadable Barcode" (or "Unassigned Accession" when the specimen letter is missing), the log keeps only the last five lines, is lost on leaving the page, and has no Resolve. The queue itself is also lost on leaving the page. |
| 13 | Slide Distribution | A slide already in the queue is not refreshed by scanning it again (it only becomes active), so its status can be out of date after a scan batch has changed it. |
| 14 | Slide Distribution | **Trigger Replacement Label** calls the slide printer without the configured slide label layout (Microtomy passes it). — Fixed in Batch 669. |
| 15 | Slide Distribution | Changing a slide from physical to digital (or back) keeps the old values on the slide. The physical fields are not prefilled from the slide's saved values when it is selected again. The chain-of-custody line for a pool shows the pool's internal id. |
| 16 | Margin Exception Review | **Resolve** and **Dismiss** do not re-run the tumor board rules (they run only at sign-out, in `runMarginRuleEvaluation`). A number recorded here therefore flags a case only the next time the rules run for it. Nothing on the screen says so. — Fixed in Batch 669. |
| 17 | Margin Exception Review | The reason "No answer given yet" cannot occur from the current extraction (an empty answer is skipped, not flagged). Resolved and dismissed items are not listed anywhere, so there is no history or undo. Resolve cannot record "less than" or "greater than". Nothing found writes an audit entry for Resolve or Dismiss. — Fixed in Batch 669 for the history list and the audit entry (undo was ruled not required). Still open, out of scope: Resolve cannot record "less than" or "greater than", and the reason "No answer given yet" is still unreachable. |
| 18 | WSI Viewer | Nothing in the application opens `/wsi-viewer?caseId=...`. **Launch in Viewer** opens the vendor's configured address, and the only seeded address ("[DEMO ONLY] Sample WSI Viewer") points to example.com. The route exists only when demonstration tools are built in, has no screen permission, ignores `accessionNumber`, shows only the first specimen and prints the patient name as "Last, First" regardless of language. |
| 19 | Add-On Orders | **Mark Block Retrieved** and **Flag Exception** are not permission-gated (only Place, Modify, Cancel and Approve are). The order list shows only slides with an ordering pathologist. A refused block aborts the whole submit. Priority is recorded and shown in tracking only. — Fixed in Batch 669 for the two permissions. Still open: the order list shows only slides with an ordering pathologist or an open exception, a refused block aborts the whole submit, priority is recorded and shown in tracking only. |
| 20 | Add-On Orders | "Primary pathologist" prints `order.assignedTo` as stored (possibly an id, not a name). The IHC panel presets are a fixed list; a panel stain missing from the stain dictionary is dropped without a message. — Fixed in Batch 669 for the primary pathologist name and the missing-panel-stain warning. Still open: the IHC panel presets are a fixed list. |
| 21 | All three stations | The Pathology Workspace tile names (Microtomy Workspace, Embedding Workspace, Slide Distribution Workspace) differ from the page titles (Microtomy Workstation, Embedding Station, Slide Distribution Station). Already noted in the Pathology Workspace article; repeated here for the screen titles. |
