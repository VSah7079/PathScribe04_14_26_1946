# Findings while writing the Molecular articles (Batch 666, Oct 24, 2026)

| # | Where | Finding |
|---|---|---|
| 1 | Control Rules gating | `/molecular-control-rules` is gated by the Molecular screen permission, not Configuration. Any Molecular Technologist can open it; changing rules needs `config:molecular-control-rules:manage` (Admin by default). — Fixed in Batch 669: view-only without the manage permission (a note says so; the service checks it again); Lab Director seeded with it. Open: neither Admin nor Lab Director holds the Molecular screen, so neither reaches the page by default (decision for Pete). — Fixed in Batch 669: Control Rules no longer needs the Molecular screen; it has its own view capability (`config:molecular-control-rules:view`; manage needs it), so Admin, Lab Director and QA Reviewer reach it by default. |
| 2 | Order Queue page | `/molecular-order-queue` is a demo page fixed to seed case S26-5003-CYT-001-A with no Home tile. It shares the name "Molecular Order Queue" with the unrelated in-house Order Queue tab. Consider renaming one. It uses the Configuration screen permission (Admin, Template Author, Template Approver, Lab Director). |
| 3 | Order Queue page | Each Positive press on the standalone assay uses a new message id, so each press fires another reflex order. The outcome line shows raw codes (`already-applied`, `case-not-found`, ...) untranslated. No way to clear entries. — Fixed in Batch 669 (one reflex order per specimen; outcome codes translated). Not done: a way to clear queue entries. |
| 4 | Accessioning link | A protocol task marked "send outbound order" raises an `order.molecular` outbound-queue entry only. It never reaches the in-house engine, which is fed only by Add-on Orders. Confirm this is intended. |
| 5 | Page title | The page title is "Molecular Workspace"; code and docs say "Molecular Workcenter". The add-on page also says "Workcenter's Order Queue". |
| 6 | Dispatch Worklist | `dispatchMolecularWorklist` sets `worklistDispatchedAt` but not `status: 'active'`. A dispatched batch stays Draft on the Worklist tab until results arrive; the Active tab fills only from seed data. — Fixed in Batch 669. |
| 7 | Dispatch Worklist | Dispatch uses a plain `fetch` to `/api/v1/events/molecular-worklist`, not the simulated engine receiver used by other outbound messages. In a deployed demo it fails. Its "could not reach" and "rejected HTTP n" messages are English constants shown in every language. — Fixed in Batch 669. |
| 8 | Dispatch scan check | The deck check needs a deck slot on the batch. A batch created without one can never pass, and batches cannot be edited, so it needs Clone & Supersede. Plate and deck barcodes can only be scanned, not typed. |
| 9 | Clone & Supersede | The clone clears every patient well, including wells bound to in-house orders. The orders are not moved. Take off plate then fails with `plateNotDraft` on the superseded plate, leaving only Cancel. A refused clone shows a raw English service message. — Fixed in Batch 669. |
| 10 | Plate builder, control well panel | Typing Control Lot Number sets the control id to the first character typed and it is never updated, so Trace shows a one-letter id. Expected value is always NEGATIVE, even for positive controls, and cannot be edited. The Control Expiration box has no value binding, so it shows blank when the well is reselected. — Fixed in Batch 669. |
| 11 | Run Results | The blocked banner says results "require manual review before sign-out", but the screen has no review or release control and records no reviewer decision. |
| 12 | Auto-fill | Auto-fill makes every empty well a patient well needing a barcode. A plate meant for Order Queue orders must be built controls-only, and the screen does not say so. |
| 13 | Rack | A tube cannot be removed or replaced once scanned in, and racks cannot be deleted. Capacity limits (1-384) are enforced by the input box only. Tubes can still be loaded after placement. |
| 14 | Control Rules | Edit does not check for a duplicate assay (only Create does). No check that a fixed well exists on a plate layout or that a control type is not listed twice. A rule with no controls saves. Saving and deleting take no reason. A refusal for lack of permission is silent. — Partly fixed in Batch 669: duplicate assay checked on Edit, a rule with no controls refused, a reason recorded on save and delete, and a permission refusal is shown. Not done: a fixed well checked against a plate layout, and a control type listed twice. |
| 15 | Hotkeys | Ctrl+Alt+Shift+N (Create Plate) is also Create Container and Add Note. Ctrl+Alt+Shift+P (Place Rack) is also Preview Report and Slide Checkout. Not in HOTKEY_DECISIONS.md; runtime clash not verified. |
| 16 | Order Queue tab | Live refresh needs the live-update hub. Without it the tab reads once and after the person's own actions. |
